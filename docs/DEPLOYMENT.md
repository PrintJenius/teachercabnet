# Teacher Cabinet 배포 가이드 (Supabase + Render)

이 문서는 **Supabase**(DB·파일) + **Render**(프론트·백엔드·RAG 서버) 중심으로 프로덕션을 올리기 위한 체크리스트입니다.

> **전제:** Pinecone·Google Gemini API는 별도 계정·API 키가 필요합니다. RAG(수업 자료 검색)에 사용됩니다.

---

## 1. 아키텍처 (권장)

```
[Render Static Site]     https://app.example.com          ← frontend (Vite build)
        │  fetch /api, /uploads (같은 도메인 또는 API URL)
        ▼
[Render Web Service]     https://api.example.com          ← Spring backend (8080)
        ├─► Supabase PostgreSQL
        ├─► Supabase Storage (업로드 이전 후)
        └─► [Render] https://rag.example.com              ← rag-server (8001)

[외부]
        Pinecone (벡터 DB)
        Google Gemini API
```

| Render 서비스 | 루트 디렉터리 | 런타임 | 포트 |
|---------------|---------------|--------|------|
| `teachercabinet-frontend` | `frontend` | Static | — |
| `teachercabinet-api` | `backend` | Java 17 | `$PORT` → 8080 |
| `teachercabinet-rag` | `rag-server` | Python 3.11+ | `$PORT` |

**배포하지 않아도 되는 것 (오프라인/배치):** `crawler`, `media-text-pipeline`, `rag-ingest` — 로컬 또는 Render Cron으로 데이터 적재 시에만 실행.

## 2. 배포 전 코드·설정 수정 (필수)

현재 저장소 그대로는 프로덕션에 올리기 어렵습니다. 아래를 **배포 전**에 처리하세요.

| # | 항목 | 현재 상태 | 필요 작업 |
|---|------|-----------|-----------|
| 1 | DB | Supabase Postgres (`SPRING_DATASOURCE_*` in `.env`) | [SUPABASE_LOCAL.md](./SUPABASE_LOCAL.md) 참고 |
| 2 | 파일 저장 | `./storage` 로컬 디스크 | Supabase Storage 연동 (4절) 또는 Render Disk(비권장) |
| 3 | CORS (Spring) | `SecurityConfig`에 `localhost:5173` 고정 | `FRONTEND_ORIGIN` 환경변수 반영하도록 수정 |
| 4 | 프론트 API | dev 프록시만 사용 (`vite.config.js`) | 프로덕션 API 베이스 URL 또는 Static Site `_redirects` |

## 3. MySQL → Supabase Postgres 이전 순서

### 3.1 순서 (권장)

1. **Supabase 프로젝트 생성** (리전: 사용자와 가까운 곳, 예: Northeast Asia)
2. **Settings → Database**에서 Connection string 확인  
   - Spring: **Session mode** 또는 **Transaction pooler** (JPA는 보통 5432 direct 또는 pooler 6543)
3. **로컬에서 Postgres 연결 테스트** (빈 DB)
4. **`backend/pom.xml`** — MySQL 드라이버 제거, Postgres 추가:

```xml
<dependency>
    <groupId>org.postgresql</groupId>
    <artifactId>postgresql</artifactId>
    <scope>runtime</scope>
</dependency>
```

5. **`application-prod.yaml`** (또는 Render 환경변수) — datasource 교체 (5.2절 예시)
6. **스키마 생성** (택 1)
   - **A)** 기존 MySQL 덤프 → Postgres 변환 (`pgloader`, [Supabase migration guides](https://supabase.com/docs/guides/platform/migrating-to-supabase))
   - **B)** 빈 DB에 `spring.jpa.hibernate.ddl-auto=update`로 1회 기동 후 엔티티 테이블 생성 → MySQL에서 데이터만 CSV/스크립트로 이전
   - **C)** `sql/` 폴더 스키마를 Postgres 문법으로 수동 변환 (ENUM, AUTO_INCREMENT → SERIAL/BIGSERIAL 등)
7. **기능 검증** — 로그인, 원아 CRUD, 일지, 수업일지, 파일 업로드, RAG 질문, 학생 분석
8. **프로덕션에서 `ddl-auto=validate` 또는 `none`** 으로 고정

### 3.2 MySQL ↔ Postgres 주의점

| MySQL | Postgres (Supabase) |
|-------|---------------------|
| `AUTO_INCREMENT` | `GENERATED BY DEFAULT AS IDENTITY` / `SERIAL` |
| `` `column` `` | `"column"` 또는 소문자 snake_case |
| `ENUM('A','B')` | `CREATE TYPE ... AS ENUM` 또는 `VARCHAR` + CHECK |
| `BOOLEAN` | 동일 (JPA가 매핑) |
| `TIMESTAMP` | `TIMESTAMPTZ` 권장 |

엔티티 11개: `Teacher`, `Student`, `StudentJournal`, `StudentJournalEntry`, `LessonJournal`, `LessonJournalMaterial`, `LessonPlan`, `CustomCategory`, 로그 3종.

### 3.3 Supabase에서 할 일

- [ ] RLS: Spring이 **service role / DB password**로 직접 접속하면 테이블 RLS는 우회됨. Supabase **Auth**를 쓰지 않는 현 구조에서는 DB를 **서버 전용**으로 두고, API 키는 Render에만 둠.
- [ ] **Database → Backups** 활성화 (Pro 플랜 이상 자동 백업)
- [ ] 연결 문자열에 `?sslmode=require` 포함

## 4. 파일 저장 → Supabase Storage (2단계)

1단계 배포에서는 **Storage 미연동** 시 Render 재배포마다 업로드 파일이 사라집니다. 가능하면 1단계와 함께 진행하세요.

| 단계 | 작업 |
|------|------|
| 1 | Supabase **Storage** 버킷 생성 (예: `uploads`, public 또는 signed URL) |
| 2 | `LocalFileStorageService` → Supabase SDK 업로드 구현 (또는 presigned URL) |
| 3 | `STORAGE_PUBLIC_URL` = Supabase public URL 또는 CDN |
| 4 | DB에 저장되는 `profile_image_url` 등이 새 URL prefix를 가리키는지 확인 |

임시 방안(비권장): Render **Persistent Disk** — 비용·백업·다중 인스턴스 문제.

## 5. 환경 변수 체크리스트

### 5.1 Supabase (대시보드에서 복사)

| 변수 | 용도 |
|------|------|
| `SUPABASE_URL` | Storage/클라이언트용 (Storage 연동 시) |
| `SUPABASE_SERVICE_ROLE_KEY` | 서버 사이드 Storage (비밀, Render만) |
| `DATABASE_URL` | `postgresql://postgres.[ref]:[password]@...` |

Spring에는 보통 분리해서 넣는 편이 낫습니다:

```bash
SPRING_DATASOURCE_URL=jdbc:postgresql://db.xxx.supabase.co:5432/postgres?sslmode=require
SPRING_DATASOURCE_USERNAME=postgres
SPRING_DATASOURCE_PASSWORD=<from Supabase>
```

### 5.2 Render — `teachercabinet-api` (Spring)

| 변수 | 예시 / 설명 |
|------|-------------|
| `SPRING_PROFILES_ACTIVE` | `prod` |
| `SPRING_DATASOURCE_URL` | Supabase JDBC URL |
| `SPRING_DATASOURCE_USERNAME` | `postgres` |
| `SPRING_DATASOURCE_PASSWORD` | Supabase DB password |
| `JWT_SECRET` | 32자 이상 랜덤 |
| `JWT_EXPIRATION_MS` | `86400000` |
| `FRONTEND_ORIGIN` | `https://app.example.com` |
| `ADMIN_LOGIN_IDS` | `admin` (쉼표 구분) |
| `ADMIN_BOOTSTRAP_LOGIN_ID` | 최초 1회 관리자 생성용 loginId (이미 있으면 무시). **운영에서는 생성 후 비우기 권장** |
| `ADMIN_BOOTSTRAP_PASSWORD` | 최초 1회 관리자 비밀번호 (Render env에만, 레포에 커밋 금지) |
| `ADMIN_BOOTSTRAP_NICKNAME` | (선택) 기본 `관리자` |
| `RAG_SERVER_BASE_URL` | `https://teachercabinet-rag.onrender.com` |
| `RAG_NAMESPACE` | `play_data` |
| `RAG_TOP_K` | `5` |
| `STORAGE_LOCAL_DIR` | Storage 이전 전: `/tmp/storage` (휘발성 주의) |
| `STORAGE_PUBLIC_URL` | `https://api.example.com` 또는 Supabase CDN |
| `SERVER_PORT` | Render가 주입하는 `$PORT` 사용 시 `server.port=${PORT}` 설정 필요 |

**`application-prod.yaml` 예시** (`backend/src/main/resources/`):

```yaml
spring:
  datasource:
    url: ${SPRING_DATASOURCE_URL}
    username: ${SPRING_DATASOURCE_USERNAME}
    password: ${SPRING_DATASOURCE_PASSWORD}
    driver-class-name: org.postgresql.Driver
  jpa:
    hibernate:
      ddl-auto: validate
    properties:
      hibernate:
        dialect: org.hibernate.dialect.PostgreSQLDialect

server:
  port: ${PORT:8080}

app:
  frontend-origin: ${FRONTEND_ORIGIN}
  jwt:
    secret: ${JWT_SECRET}
    expiration-ms: ${JWT_EXPIRATION_MS:86400000}
  rag-server:
    base-url: ${RAG_SERVER_BASE_URL}
    namespace: ${RAG_NAMESPACE:play_data}
    top-k: ${RAG_TOP_K:5}
  admin:
    login-ids: ${ADMIN_LOGIN_IDS:admin}
  storage:
    local-dir: ${STORAGE_LOCAL_DIR:./storage}
    public-url-prefix: ${STORAGE_PUBLIC_URL}
    upload-path-prefix: /uploads
```

**Render Build & Start (예시):**

```bash
# Build Command
./mvnw -DskipTests package

# Start Command
java -Dspring.profiles.active=prod -jar target/server-0.0.1-SNAPSHOT.jar
```

### 5.3 Render — `teachercabinet-rag`

| 변수 | 설명 |
|------|------|
| `RAG_SERVER_HOST` | `0.0.0.0` |
| `PORT` | Render 자동 (uvicorn이 읽도록 설정 필요) |
| `GEMINI_API_KEY` | Google AI Studio |
| `PINECONE_API_KEY` | Pinecone |
| `PINECONE_INDEX` | `teachercabinet-play` |
| `PINECONE_NAMESPACE` | `play_data` |
| `CORS_ORIGINS` | `https://app.example.com` (Spring이 server-to-server면 RAG CORS는 덜 중요) |
| `CHAT_MODEL` / `CHAT_MODEL_FALLBACK` | `config.py` 기본값 참고 |

**Start Command 예시:**

```bash
cd rag-server && pip install -r requirements.txt && uvicorn app.main:app --host 0.0.0.0 --port $PORT
```

`rag-server/app/config.py`에 `rag_server_port`가 고정 8001이면, Render용으로 **`PORT` 환경변수 우선** 읽도록 수정 권장.

### 5.4 Render — `teachercabinet-frontend` (Static Site)

**방법 A — API와 같은 도메인 (권장)**  
Static Site의 **Redirects/Rewrites**:

| Source | Destination |
|--------|-------------|
| `/api/*` | `https://api.example.com/api/:splat` |
| `/uploads/*` | `https://api.example.com/uploads/:splat` |
| `/*` | `/index.html` (SPA) |

프론트 코드는 그대로 `fetch('/api/...')` 사용 가능.

**방법 B — API URL 분리**  
빌드 시 `VITE_API_BASE=https://api.example.com` 추가 후, `fetch` 유틸에서 prefix 사용 (코드 수정 필요).

```bash
# Build Command
cd frontend && npm ci && npm run build

# Publish Directory
frontend/dist
```

## 12. 문제 해결

| 증상 | 확인 |
|------|------|
| RAG 연결 실패 | Spring `RAG_SERVER_BASE_URL`, rag-server 실행, Pinecone namespace `play_data` |
| CORS 오류 | `FRONTEND_ORIGIN`, `SecurityConfig` allowedOrigins, rag `CORS_ORIGINS` |
| 401 전역 | JWT 만료, `Authorization: Bearer` 헤더 |
| 업로드 404 | Storage 미연동 시 Render 재배포로 파일 소실 — M4 진행 |
| DB connection | Supabase IP allowlist(필요 시), SSL, pooler 포트 |
